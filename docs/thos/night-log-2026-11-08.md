# Night shift 2026-11-08: hardware through ACPI

All verified in QEMU only (the Acer is not reachable yet). Each item has a test.

| Component | How | Where / test |
|---|---|---|
| ACPI AML interpreter | lai (MIT, `third_party/lai`), own kernel thread, `noacpi` on the command line (boot menu: "safe start") skips it | `kernel/src/acpi_aml.rs`, `kernel/c/acpi_glue.c`; `cargo xtask acpi-test` |
| Embedded controller | bounded polling driver (lai's own waits forever), `_REG`, `_Qxx` events polled every 100 ms | `acpi_glue.c` |
| Battery, AC, thermal zones, lid | `/proc/power` (`key: value` lines), also in `hwreport` | acpi-test (synthetic SSDT `xtask/testdata/fake-power.asl`, compile with `iasl`) |
| CPU temperature | DTS MSR, only when CPUID.06H reports it | `acpi_aml.rs::cpu_temp` |
| Power button | PM1 status polled, short press shuts down | `powerbutton-test` |
| Backlight | ACPI video `_BCL/_BCM/_BQC`, syscall `THOS_BASE+2`, `thosbl [percent]` | acpi-test |
| Volume | HDA output amplifiers, syscall `THOS_BASE+3`, `thosvol [percent]` | `volume-test` |
| Lid | closing turns the backlight off, opening restores it | `acpi_aml.rs::lid_follow` (not testable with the static fake lid) |
| UI | dock shows battery %, Settings > Power & sound (values + sliders) | `desk-battery-test`, `desk-power-test` |

Open on the real Acer: AML of the real DSDT, EC access, which `_Qxx` the Fn keys raise, whether `_BCM` moves the Intel backlight.
If the Acer hangs at boot: boot "safe start" and read the lock-up report on screen.
